## 当前真实验证状态（2026-09-09）

第一阶段已在独立 Python 环境中对真实微信源加密数据库执行只读探测，固定使用
`wechatauto-replica 1.2.1 / 798989c9b61066c120b59ceba636b557b776ff7f`。用户确认登录并打开图片后，
最终定向结果为 `blocked`（部分成功，不是完整兼容性通过）：发现 35 个加密数据库（约 1.38 GB），
适配器初始化成功，进程内取得 27 个数据库密钥、8 个仍未取得；一个真实库产生新缓存并通过
`PRAGMA quick_check=ok`，匿名会话数为 1。随后定位并复制了一个真实加密图片 `image.dat`，但主微信
进程的一次性图片 AES 密钥扫描返回 `ImageKeyNotFound`，没有生成可预览图片。探测只写应用私有
session/cache，未持久化密钥，未运行 cleanup/executor；源 `.db` 内容 hash/大小在后续稳定复核中未变。

只有数据库和媒体小样本门禁都真实通过后，才可开始 `P4-REAL-DB-01`、`P4-REAL-MEDIA-01` 的实现与
后续打包；当前不得标记真实 Beta 或发布包完成。

## 用户必须得到的成品

用户只启动“微信空间管理器”一个软件。软件自动发现本机微信 4.x 数据目录和账号，直接以
微信源目录为只读输入，在应用自有缓存目录内完成数据库解密、消息/联系人映射和媒体解码。
用户不需要预先复制 `Rec`、运行外部脚本、手工解密数据库或准备 mapper JSON。

首个真实 Beta 至少提供：

- 自动发现一个或多个本机微信账号，并允许用户选择账号；
- 直接读取微信加密数据库，按联系人、群聊、时间、媒体类型和大小筛选；
- 图片、缩略图、语音、视频和普通文件的可用性状态；
- 对已落盘图片直接解密并预览，原图不存在时明确显示“仅有缩略图”；
- 所有解密数据库、密钥缓存、预览和临时副本都归入一个应用缓存根；
- 显示缓存占用、缓存位置、单次会话占用，并提供“清除解密缓存”和“清除全部本地缓存”；
- 不写微信数据库，不修改微信源文件；首个 Beta 不包含隔离、回收站或永久删除。

## 已选真实解密基础

候选基础为
[`fanyuantaier/wechatauto-replica`](https://github.com/fanyuantaier/wechatauto-replica)，
固定版本 `v1.2.1` / commit `798989c9b61066c120b59ceba636b557b776ff7f`，许可证
Apache-2.0。2026-09-09 核对时，该提交同时是上游 `main` 和 `v1.2.1`。

它提供真实微信 4.x 能力：

- 从 `Weixin.exe` 进程内存只读提取并校验 SQLCipher 4 数据库密钥；
- 将数据库页和有效 WAL 帧解密到指定工作目录；
- 读取真实 contact/session/message/media/message_resource 等数据库；
- 解密微信图片 v1/v2 `.dat`，支持 AES/XOR 组合格式；
- 从媒体数据库导出 SILK 语音，并定位已存在的视频和普通文件。

不得直接把整个上游包的发送、OCR 和 UI 自动化能力暴露给本应用。实现时建立独立适配层，
只开放只读数据库和媒体接口；固定 revision，并随发布包携带 Apache-2.0 LICENSE、来源和修改
说明。

## 建议拆分与所有权

### P4-REAL-DB-01（`wechat_db_adapter`）

- 新增真实微信适配器，不替换现有 synthetic adapter。
- 自动发现数据根和账号；也允许用户显式选择。
- 把上游 `WeChatDB` 的异常、密钥缓存和临时数据库隔离在 adapter 内。
- 输出现有 `DatabaseEvidenceEnvelope` 或版本化扩展契约，不输出正文到日志。
- 支持真实 contact、session、message 分库和 message_resource 映射。
- 所有数据库解密产物只写应用缓存根；源库、WAL、SHM 始终只读。

### P4-REAL-MEDIA-01（`decoder`）

- 适配上游 `MediaDownloader` 的 v1/v2 图片解密，不再以通用 XOR 模拟真实格式。
- 输入可以指向源目录中的真实 `.dat`；输出只能写应用缓存根。
- 支持原图/缩略图状态，输出后用 Pillow 和文件魔数做完整性验证。
- 语音以 SILK 导出并提供本地播放所需的受控转码；视频/文件只读取已落盘内容。
- 任何密钥、绝对源路径不得进入 artifact、日志、异常或索引。

### P4-REAL-WORKFLOW-01（`application_workflow`）

- 将账号发现、数据库解密、扫描、映射、索引和媒体预览编排成一次应用内流程。
- 用户不再手工准备 database copy、copy root 或 mapper JSON。
- 内部可以创建一致性快照和缓存，但对用户表现为“直接读取微信数据”。
- 为每次运行创建 session manifest，登记解密数据库、预览、转码和密钥缓存，支持整体清理。
- 首个 Beta 禁用现有执行器的文件移动和删除入口。

### P4-REAL-GUI-01（`gui_shell`）

- 首次启动提供“自动检测微信数据”向导和账号选择。
- 展示联系人/群聊、时间范围、媒体类型、大小、原图状态和缓存占用筛选。
- 表格中的图片可以请求缩略图或原图预览；失败要显示明确原因。
- 设置页提供缓存根、容量上限、过期策略和两级清除按钮。
- 首个 Beta 隐藏清理任务页的执行按钮，或整体切换为只读浏览模式。

### P4-REAL-INTEGRATION-01（`integration`）

- 公共 CI 继续只使用合成夹具。
- 增加本机手工 harness：只输出版本、成功/失败、匿名数量、字节数和错误码分布。
- 私有验收必须证明输入来自真实微信源目录，不能拿预先解密数据库冒充。
- 私有验收只运行在用户电脑，不把路径、账号、联系人、正文、密钥或媒体写入 Git。

### P4-REAL-PACKAGE-01（`packaging`）

- 生成 Windows 便携包/安装包，包含真实只读适配器及其许可证材料。
- 在无 Python 的干净 Windows 用户环境验证自动发现、数据库读取、筛选和媒体预览。
- 缓存全部位于应用拥有的单一根目录；卸载时默认保留，用户明确选择后才清理。
- 首个发布包不包含清理真实微信文件的能力。

## 阶段门禁

1. **环境门禁**：固定上游版本可安装；当前微信版本可被识别；导入只读模块成功。
2. **真实数据库门禁**：从源数据库产生新解密缓存；SQLite quick/integrity check 通过；能读取匿名
   会话和消息计数。
3. **真实媒体门禁**：从真实消息定位一个源 `.dat`，在独立缓存中得到可打开的图片；记录格式
   类型和成功/失败，不记录内容。
4. **应用链路门禁**：不依赖用户手工解密，GUI 能完成账号选择、联系人/时间筛选和预览。
5. **缓存门禁**：应用列出的缓存总量与磁盘一致；清理缓存只命中应用缓存根，不触碰微信源。
6. **发布门禁**：干净环境安装/启动通过；许可证完整；只读模式中没有删除、移动或数据库写入
   入口。

## 私有小样本验收标准

用户退出可能改写数据的操作或明确接受在线只读模式后，由本机执行者：

1. 选择一个真实账号和少量真实会话，但不在报告中记录名称或 ID。
2. 从微信源目录直接读取并解密至少一个 contact/session/message 数据库到专用缓存。
3. 只输出匿名统计：数据库数量、完整性结果、会话数、消息数和错误码。
4. 选取一条真实图片消息，将对应加密媒体复制到私有 session 目录，并从该副本解密预览。
5. 验证图片格式、像素可读和源文件 hash/mtime 未变化；不提交图片。
6. 验证应用能按匿名联系人、时间范围和媒体类型筛选到该记录。
7. 验证“清除解密缓存”预览只列出应用缓存根内的对象；在正式实现前不实际删除。

## 明确禁止误报

- 合成 XOR 图片通过，不等于微信 4.x 图片解密通过。
- 打开已经解密的 SQLite，不等于能从微信源数据库自动解密。
- 默认 GUI 能启动，不等于真实账号、联系人、时间筛选和媒体预览已经可用。
- `ready_for_human` 只表示公开门禁完成，不是本目标的真实兼容证据。
- 未完成真实小样本门禁前，不得制作“可读取真实微信数据”的发布包。

## 回滚

真实适配器必须是可选后端。回滚时移除该后端和独立缓存，不修改现有合成契约、索引及安全
执行器；微信源目录在任何情况下都不需要回滚，因为本目标不对其写入。
