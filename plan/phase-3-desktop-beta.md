## GUI 信息架构

左侧导航保持五个顶层页面：

1. **数据源**：账号根目录、只读扫描、数据库副本、索引状态和上次更新时间。
2. **空间总览**：账号/联系人/类型/年份聚合，显示已索引大小和可安全选择大小。
3. **精确筛选**：条件构造器、结果表、分页、排序、预览和固定选择快照。
4. **清理任务**：计划摘要、排除原因、身份预检、Dry Run、隔离/回收站、收据与恢复。
5. **设置与缓存**：解码缓存和元数据索引占用、上限、清除、日志隐私和版本信息。

所有长任务进入后台线程池，提供进度、取消和过期结果丢弃。GUI 只调用
`application` facade，不直接调用 `Path.unlink`、`shutil.move`、数据库写入或微信目录 API。

## 精确筛选矩阵

| 维度 | 支持方式 | 安全语义 |
| --- | --- | --- |
| 账号 | 单选/多选 | 不得跨账号合并执行计划 |
| 联系人/群聊 | 搜索、多选、未映射 | 未映射可查看但默认不可清理 |
| 会话类型 | 私聊、群聊、系统/未知 | 系统/未知默认保护 |
| 媒体类型 | 图片、视频、语音、文件、缩略图、其他 | `db_storage`、收藏和未知目录永远排除 |
| 消息时间 | 起止、相对区间、按年/月 | 与文件观测时间分开，不得混用 |
| 文件观测时间 | 起止、多久未变化 | 只表示扫描时文件属性，不推断消息发送时间 |
| 大小 | 最小/最大、预设区间 | 汇总同时显示条目数与字节数 |
| 映射质量 | 高/中/低、冲突、无映射 | 第一版仅高置信且无冲突可进入计划 |
| 文件状态 | 存在、丢失、变化、重复候选 | 变化/丢失必须在预检中跳过并留收据 |
| 保留策略 | 每会话保留最近 N 天、最近 N 个、收藏/手工标记 | 保留规则优先于包含条件，结果必须说明排除原因 |
| 组合逻辑 | 组内 OR、组间 AND、保存本机预设 | 生成版本化 `FilterSpec` 和摘要散列 |
| 选择范围 | 当前页、当前筛选全部、逐项勾选 | 固化为 `SelectionSnapshot`，数据变化即失效 |

结果表至少显示：选择状态、账号、联系人/群、类型、消息时间、文件时间、大小、映射
置信度、冲突/保护原因、预览状态。默认排序为大小降序；服务端分页，禁止把全部记录
加载进 GUI 内存。

## 安全执行流程

```text
FilterSpec -> FilterResultSummary -> SelectionSnapshot
           -> immutable CleanupPlan (scan lineage + digest + expiry)
           -> preflight identity recheck
           -> Dry Run receipt
           -> explicit user confirmation
           -> quarantine OR recycle bin
           -> per-file CleanupReceipt + recovery locator/state
```

- 计划默认拒绝中/低置信、冲突、未映射、受保护、正在写入和越界路径。
- 中置信若未来开放，必须是绑定具体计划摘要的显式确认；默认值永远为 false。
- 隔离/回收站统计“选择字节/处理字节”，不得谎称已立即释放磁盘空间；可另记磁盘空闲
  变化但不作为逐文件事实。
- Windows 执行前重验绝对规范路径、账号根、大小、mtime、计划摘要，并优先使用卷序列号/
  文件 ID 或句柄绑定复核。任一不匹配即跳过。

## 性能与验收预算

- 面向约 100 GiB 数据目录，扫描与索引应流式处理；GUI 首屏不等待全量媒体解码。
- 默认分页 200 条，允许 50/100/200/500；排序和聚合在 SQLite 侧完成。
- 取消后不再把旧查询结果写回当前页面；进度事件不得包含联系人名、正文或绝对路径。
- 10 万条合成索引的典型分页查询目标低于 300 ms；冷启动数据库迁移和大规模扫描另行
  计时并显示进度，不以此目标掩盖真实耗时。
- GUI 自动验收用 Qt offscreen；最终还需真实 Windows 显示、DPI、中文路径和打包 smoke。

## 回滚

每个目标只回滚其独立所有权目录。契约通过新增兼容版本演进，不覆盖旧 schema。R3
执行器发生异常时关闭执行入口但保留只读分析；索引和解码缓存均可整目录清除重建。
真实数据操作永远不作为 Agent 的自动回滚手段。
